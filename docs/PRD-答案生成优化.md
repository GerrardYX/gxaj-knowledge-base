## 1. 问题分析

### 1.1 现状问题

| 问题点 | 描述 | 影响 |
|--------|------|------|
| **分块粒度不合理** | 当前按段落分块，导致同一场景的内容被拆分到多个 chunk | 检索时返回碎片化信息 |
| **相似度偏低** | 搜索"如何新签合同"返回 46%、46%、23%、8% 等低相似度结果 | 用户难以找到真正相关的答案 |
| **缺乏答案生成** | 系统直接返回文档 chunk 内容，未生成总结性答案 | 用户需要自己从大段文字中提取信息 |
| **来源混淆** | 多个场景文档混杂（保租房企业合同、续签合同、新用户首次登录） | 检索结果与用户意图不匹配 |

### 1.2 用户体验痛点

```
用户场景：企业 HR 想要了解"新签合同"的流程
期望：系统给出清晰的新签合同步骤清单
实际：系统返回 4 篇文档的片段，需要用户自己阅读理解
```

### 1.3 问题根因

1. **Chunk 边界划分**：按固定长度/段落切分，破坏了内容的语义完整性
2. **检索-生成脱节**：检索结果直接展示，未经过 LLM 加工成答案
3. **阈值缺失**：所有检索结果都展示，低质量结果干扰用户

## 2. 优化方案

### 2.1 分块策略优化

#### 2.1.1 核心原则

| 原则 | 说明 |
|------|------|
| **场景完整性** | 每个 chunk 包含一个完整的业务场景 |
| **语义自洽** | Chunk 本身能独立表达完整意思 |
| **长度适中** | 单个 chunk 长度控制在 300-800 字 |

#### 2.1.2 分块方式

| 分块类型 | 适用内容 | Chunk 大小 |
|----------|----------|------------|
| **场景块** | 业务流程、操作指引 | 400-600 字 |
| **定义块** | 概念解释、制度说明 | 200-400 字 |
| **表格块** | 对比表格、清单列表 | 300-500 字 |
| **表单块** | 填写模板、示例文档 | 200-300 字 |

#### 2.1.3 分块元数据设计

每个 Chunk 必须包含以下元数据：

```json
{
  "chunk_id": "string",
  "scene_code": "string",           // 场景编码：如 "CONTRACT_NEW"
  "scene_name": "string",            // 场景名称：如 "新签合同"
  "parent_doc_id": "string",         // 所属文档 ID
  "doc_title": "string",             // 文档标题
  "chunk_order": "number",           // 在文档中的顺序
  "keywords": ["string"],            // 关键词标签
  "intent_queries": ["string"]      // 可能的问题表述
}
```

#### 2.1.4 分块示例

**原始文档结构**：
```
一、新签合同流程
  1. 发起签约
  2. 合同审批
  3. 合同签署
二、续签合同流程
  ...
```

**优化后的 Chunk 结构**：

| Chunk ID | 场景名称 | 内容摘要 | 长度 |
|----------|----------|----------|------|
| C001 | 新签合同-发起签约 | 介绍如何发起新签，包括入口、操作步骤 | 520字 |
| C002 | 新签合同-合同审批 | 合同审批流程、审批节点说明 | 480字 |
| C003 | 新签合同-合同签署 | 签署方式、签署状态查看 | 350字 |
| C004 | 续签合同-概述 | 续签条件、触发机制说明 | 400字 |
| ... | ... | ... | ... |

### 2.2 答案生成流程设计

#### 2.2.1 流程架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户查询                                  │
│                   "如何新签合同"                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                       1. 检索阶段                                │
│  • 向量检索：基于用户 query 检索相关 chunks                      │
│  • 可选：关键词召回补充                                          │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                       2. 筛选阶段                                │
│  • 相似度阈值过滤（≥30%）                                       │
│  • 场景去重（同一场景保留 top 1-2 chunks）                      │
│  • 意图匹配度排序                                                │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                       3. 生成阶段                                │
│  • 构建 Prompt（包含用户问题 + 筛选后的 chunks）                │
│  • 调用 LLM 生成总结性答案                                      │
│  • 提取关键引用                                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                       4. 输出阶段                                │
│  • 返回结构化答案                                                │
│  • 附带来源引用                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.2.2 各阶段详细说明

**阶段 1：检索**
- 使用语义向量检索，召回 Top 20 个候选 chunks
- 可结合 BM25 关键词召回作为补充

**阶段 2：筛选**
- 过滤相似度 < 30% 的结果
- 同场景结果去重，保留最相关的 1-2 个
- 按相似度+场景权重综合排序

**阶段 3：生成**
- 将筛选后的 chunks 构造成上下文
- 调用 LLM 生成简洁的总结性答案
- 要求 LLM 不直接复制原文，而是提炼总结

**阶段 4：输出**
- 返回结构化 JSON 格式
- 包含答案文本 + 来源列表

---

### 2.3 相似度阈值和过滤策略

#### 2.3.1 阈值设置

| 阈值范围 | 处理策略 | 说明 |
|----------|----------|------|
| ≥70% | 强相关，优先展示 | 直接用于答案生成 |
| 50%-70% | 中等相关，纳入生成 | 用于答案生成 |
| 30%-50% | 弱相关，谨慎使用 | 视情况纳入，排在后面 |
| <30% | 过滤不展示 | 视为不相关，不返回 |

#### 2.3.2 多结果处理

| 场景 | 处理策略 |
|------|----------|
| **单场景多结果** | 同场景保留 top 1-2 个 chunks |
| **多场景结果** | 按相似度排序，每个场景至少保留 1 个 |
| **结果不足** | 相似度低于阈值时，返回"未找到相关答案"提示 |

#### 2.3.3 兜底策略

- 检索结果为空时：返回引导性问题或热门问题推荐
- 所有结果低于阈值时：返回"未找到完全匹配的内容，以下是相近信息："
- 单个 chunk 过长时：截取最相关的段落

## 3. 提示词模板设计

### 3.1 答案生成 Prompt 模板

```markdown
## 角色
你是一个专业的企业 HR 助手，擅长从文档中提取关键信息并清晰解答用户问题。

## 用户问题
{{user_query}}

## 相关文档内容
{{#each chunks}}
---
【文档来源】{{this.doc_title}}
【场景】{{this.scene_name}}
【内容】
{{this.content}}
---
{{/each}}

## 回答要求
1. 基于以上文档内容，用简洁专业的语言回答用户问题
2. 不要直接复制原文，要提炼总结
3. 如果多个文档内容相关，合并整理
4. 步骤类内容用清晰的列表格式呈现
5. 答案控制在 300 字以内
6. 在答案末尾注明参考来源

## 输出格式
【答案】
（此处为总结性答案）

【参考来源】
- {{doc_title}} - {{scene_name}}
```

### 3.2 无相关结果 Prompt

```markdown
## 角色
你是一个友好的企业 HR 助手。

## 用户问题
{{user_query}}

## 处理策略
用户的问题没有找到完全匹配的内容，请生成一个引导性回复。

## 输出格式
抱歉，未找到与"{{user_query}}"直接相关的内容。

建议您：
1. 尝试使用更通用的关键词
2. 浏览以下相关话题：
   - 新签合同流程
   - 合同管理操作指引
   - 常见问题 FAQ

如有其他问题，欢迎继续咨询。
```

### 3.3 多场景聚合 Prompt（可选）

```markdown
## 角色
你是一个专业的企业 HR 助手，擅长将多个相关场景整合成完整答案。

## 用户问题
{{user_query}}

## 场景列表
{{#each scenes}}
### {{this.scene_name}}
{{this.summary}}
{{/each}}

## 回答要求
用户问题涉及多个场景，请整合成一个完整的答案框架，按逻辑顺序组织内容。
```

## 5. 验收标准

### 5.1 功能验收

| 验收项 | 标准 | 测试方法 |
|--------|------|----------|
| 分块粒度 | 每个 chunk 包含完整单一场景，长度 300-800 字 | 随机抽查 chunk 样本 |
| 检索准确率 | Top 5 结果中至少 3 个与 query 高度相关（≥50%） | 人工评估检索结果 |
| 相似度阈值 | 低于 30% 的结果不展示 | 验证日志/响应 |
| 答案生成 | 答案不直接复制原文，是总结性内容 | 人工审查生成结果 |
| 来源引用 | 每个答案附带 1-3 个来源文档 | 验证输出结构 |
| 回答长度 | 单次回答控制在 300 字以内 | 统计回答长度分布 |

### 5.2 体验验收

| 验收项 | 标准 |
|--------|------|
| **回答质量** | 用户能直接获取答案，无需二次阅读文档 |
| **场景覆盖** | 同文档同场景只出现一次 |
| **去重效果** | 相似的 chunk 不会被重复召回 |
| **响应时间** | 端到端响应 < 3 秒 |

### 5.3 测试用例

| 用例 | 输入 | 期望输出 |
|------|------|----------|
| 场景完整查询 | "如何新签合同" | 返回新签合同完整流程步骤，包含来源引用 |
| 部分匹配查询 | "合同怎么签" | 返回相关内容，过滤无关文档 |
| 无匹配查询 | "公司的历史" | 返回友好提示，建议其他话题 |
| 多场景查询 | "合同相关操作" | 聚合多个场景，给出分类答案 |

## 6. 实施计划

### 6.1 优先级

| 优先级 | 任务 | 预计工作量 |
|--------|------|------------|
| P0 | 分块策略优化（按场景分块） | 高 |
| P0 | 相似度阈值过滤 | 中 |
| P1 | 答案生成 Prompt 优化 | 中 |
| P1 | 输出格式规范化 | 低 |

### 6.2 风险与对策

| 风险 | 对策 |
|------|------|
| 场景边界定义模糊 | 产品与业务共同制定场景划分标准 |
| LLM 生成质量不稳定 | 迭代优化 Prompt，建立案例库 |
| 阈值设置不合理 | 上线后收集用户反馈持续调优 |
